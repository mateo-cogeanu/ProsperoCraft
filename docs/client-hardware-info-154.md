This test improves the two F3 hardware names. It is not a Store release or a passing milestone. Standard PS5/Slim and PS5 Pro console validation are both pending. Fabric 26.2 remains held. Install [the development test app](https://github.com/mateo-cogeanu/ProsperoCraft/releases/tag/client154-hardware-info-test); it uses the existing PPSA99874 identity and replaces the installed client/server app. The unchanged public release remains 153.

## Sources and integration

26.2 F3 calls original `GLX._getCpuInfo`;26.3 and snapshots1–6 call original `DebugEntrySystemSpecs.getCpuInfo`. They format OSHI logical count and `ProcessorIdentifier.getName()` as `%dx %s`. The existing native handoff queries `hw.ncpu`, with CPUID topology fallback, and returns checked CPU fields to `ClientStartup25.installCpuInformation`. OSHI 6.9 uses the existing dependency-only SystemInfo port; snapshot 6 uses the supported OSHI 7.7.2 SPI. This change replaces only the native handoff's display name. Raw CPUID decoding, vendor/signature/family/model/stepping, count and unsupported telemetry semantics remain.

The original Vulkan paths read `VkPhysicalDeviceProperties.deviceName` through LWJGL.26.2's `com.mojang.blaze3d.vulkan` and 26.3/snapshots' RenderPearl `VulkanPhysicalDevice.deviceName` feed their device-info record; F3 presents its name and separate driver/backend fields. Pinned PS5 Mesa's winsys sets the marketing prefix to PlayStation 5 GPU, and RADV appends its compiler-family name. Its NAVI21/GFX10.3 compatibility configuration is **not console model evidence**.

A private, PS5-only Mesa property patch writes the readable name into the final `vk_properties.deviceName`, after RADV has built the genuine device properties, preserving an explicit drirc force-device-name compatibility override. The existing build recipe recompiles this source and substitutes its object alongside the existing WSI object in the private archive; pinned source and original archive remain unchanged. No vendor/device ID, UUID, feature, extension, limit, driverName, driverInfo or internal RADV marketing/family field is changed. Mesa configuration/compiler selection happens on the original fields. Other consumers of the exported name (enumeration, diagnostics and device-info labels) also see the readable name. Minecraft's known-device compatibility matching uses driver/vendor/device IDs; its name-based Apple Silicon hint remains false for both old and new PS5 names. Device selection/capability/queue logic remains original. This does not establish third-party mods' handling of arbitrary device names.

The packaged OpenGL provider is the existing OSMesa/softpipe diagnostic provider, not the game's Vulkan hardware source. Its GL_VENDOR/GL_RENDERER/GL_VERSION values remain unchanged. No official game/mod JAR, mod list, bytecode transformation, renderer/performance/heap/GC policy or desktop provider behavior changes.

## Detection and evidence

At native startup, before frontend/GPU/JVM initialization, the app calls community SDK `sceKernelGetHwModelName` from `libkernel_sys`. The reusable [runtime helper](https://github.com/mateo-cogeanu/ps5-java25-homebrew/blob/db3048febe846abd30a7ae7e3315a517a0910e16/Development/java25/platform/console_model.hpp) accepts only zero success and bounded recognized CFI strings. The native model is captured once for CPU/GPU consistency. CFI-10/11/12/20/21xx map to standard, CFI-70/71xx to Pro; unknown revisions/devkits and failure stay unknown. No firmware, CPUID brand, GPU codename, resolution or user choice selects the family. No serial API is called and raw model responses are never logged. Logs contain only family, query status and native result. Status 0 unavailable, 1 failure, 2 unterminated, 3 unrecognized, 4 recognized.

[SDK hwinfo](https://github.com/ps5-payload-dev/sdk/blob/master/samples/hwinfo/main.c) supplies the native signature, zero-success convention and 1000 byte buffer precedent. Pinned SDK v0.42 includes that example and export. This unsized API cannot be made length-aware by the caller; parsing checks termination within 1000 bytes, and does not assume a successful return is a recognized model. No Sony proprietary SDK contract or physical-console success is claimed. `client/ports/console-model-runtime.json` pins the separately published helper by commit/hash; reusable source is not duplicated here.

[Sony's manual index](https://www.playstation.com/en-us/support/hardware/manuals/) groups the recognized CFI families. Its [70xx](https://www.playstation.com/content/dam/global_pdc/en/corporate/support/manuals/ps5-docs/7000/CFI-70XX_PS5_Safety_Guide_Web%24en.pdf) and [71xx](https://www.playstation.com/content/dam/global_pdc/en/corporate/support/manuals/ps5-docs/7100/CFI-71XX_PS5_Safety_Guide_Web%24en.pdf) safety guides specify Zen 2, 8 cores/16 threads and an AMD Radeon RDNA-based GPU. [Sony's base PS5 specification page](https://contents.sony.co.kr/sony/contents/2076/contents_26.html) lists Zen 2, 8 cores/16 threads, RDNA 2 and 36 CUs. [Sony's Pro announcement](https://blog.playstation.com/2024/09/10/welcome-playstation-5-pro-the-most-visually-impressive-way-to-play-games-on-playstation/) gives 67% more CUs and 28% faster memory. 60 CUs and 576 GB/s can be inferred approximately from the base figures and rounded percentages, but those inferences are unnecessary in F3. Pro architecture is deliberately **RDNA**, not an unverified RDNA 3 label. Reference Pro clocks 3.85 GHz/2.17–2.35 GHz are not verified by these official documents and are omitted. Official 16.7 TFLOPS/16 GB GDDR6 + 2 GB DDR5 and base maximum clocks/bandwidth are also omitted to keep the labels short. None is a live measurement.

## Checks and console checklist

`tools/test_hardware_labels.py` compiles actual native labels/query integration with ASan/UBSan, checks bounds/ASCII and unchanged CPUID logical counts, compiles the exact property-patch statements with surrounding ID/capability/driver sentinels for PS5/non-PS5, and invokes all eight intact publisher game CPU entries through OSHI 6/7. The target build and full startup package checks verify metadata 154, signatures/CRC, runtime image/native regressions, all 19 resident groups, staged constructors, original game artifacts and preserved historical packages. New checks verify the packaged runtime/source hashes, main object, actual substituted RADV object/archive member, function wiring, real model-query import, absence of serial import, and all six label strings. `hardware-display-audit.json` is shipped in the app. Existing CPU/provider, launch-policy/host-Main and supported-version regressions remain relevant. See the matching validation record for measured results/checksums.

On a standard PS5/Slim, launch 154 with a working supported Vanilla instance, enter a world and open F3. Check both standard labels, the unchanged logical prefix and a separate genuine Vulkan/Mesa driver line. Repeat on an actual PS5 Pro and expect both Pro labels. Confirm normal rendering/input and return/save behavior. If either shows model unknown, retain the family/status/native-result line from the current run; do not supply a serial number. A future unknown CFI family needs public model documentation before adding a mapping. Native query behavior, line readability/truncation, both real model labels and gameplay regression remain pending independently for each console family.
