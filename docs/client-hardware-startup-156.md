# 01.000.156 optional hardware query startup repair

**Release withdrawn 2026-10-30 at the user’s request.** The test package and source tag are preserved locally/in source history. Do not use the historical release-download links below; future releases require user confirmation that the exact build works. All other releases, including 153, remain preserved.

The user reports 155 crashes immediately on launch. Cyberduck successfully retrieved the current ShadowMount debug log on 2026-10-30. Two recent PPSA99874 attempts enter a crash-candidate state within approximately one second and before the configured KStuff auto-pause. This confirms the early failure, but does not identify a faulting function or prove loader rejection. The title sandbox and mounted download directory were absent after exit; title-local startup reports were not retrievable. The raw loader report stays local.

Binary comparison found a concrete regression:153 required only libkernel.sprx, whereas154/155 added libkernel_sys.sprx via the direct sceKernelGetHwModelName import. The SDK payload hwinfo example did not establish that this extra module was loadable in an application process. The call also preceded log-sharing initialization. Host compilation and signatures failed to catch this application-loader compatibility risk.

156 removes the direct import and resolves only the optional named export through the existing sceKernelDlsym in the already-loaded kernel. The separately published runtime helper 897667e checks kernel handles 1 and 0x2001 following the SDK rtld process types, verifies a kernel resolver export first, accepts only zero-success/nonnull pointers and ignores failed outputs. No module is loaded. Missing query means model unknown and ordinary startup continues. Logging/log-sharing now start before optional lookup/invocation; build.txt records the phase, family/status, resolver handle/result and native result without raw model or serial. The unsized SDK model-query ABI remains subject to the previously documented 1000 byte buffer convention; a native internal fault is not caught. Exact invocation on both console families remains pending.

The compact 155 labels, 36/60 CU distinction,actual logical counts,OSHI providers and genuine graphics capabilities/driver/IDs remain unchanged. If this app process does not expose the model export,156 will show generic model-unknown hardware instead of guessing standard/Pro.

New package gates reject libkernel_sys and a mandatory model-query import, require the complete DT_NEEDED library set to equal the preserved 153 baseline and check log-sharing precedes lookup. Actual resolver ASan/UBSan fixtures cover both handles,missing callback/export,null pointer and failure with a poisoned nonnull output; existing model/label/original Minecraft26.2/26.3/snapshots1–6 and full package regressions run separately. The target app is compiled/linked/signed with the new helper pin and shipped object/source hashes. Tests do not establish PS5 launch recovery.
